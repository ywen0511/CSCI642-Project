## 1. 目标和边界

完成 EEGNet 与 CBraMod 在 ErrP-HRI 上的公平比较，并产生供后续 RL 使用的固定反馈概率库。

本阶段包含：数据审计、参与者划分、预处理与事件切片、模型训练、概率校准、评估、权重保存、逐 trial 概率导出、复现文档，以及代码推送与 GitHub Release 产物上传。只在 GPU 临时磁盘保存不算交付完成。

本阶段不包含：SAC、机器人环境、奖励权重调优、路线偏好扩展或新的人体 EEG 采集。不得修改项目已有论文、proposal 或其他原始材料。不要以 CBraMod 必须胜出作为验收目标。

## 2. 区分文献设置与项目设置

Kim 明确描述了以下内容：EEGNet；交叉熵；留一被试验证（LOSO）；1–20 Hz 带通；重参考；降采样至 256 Hz；事件对齐的 2 秒窗口；RL 中使用解码出的错误概率。方法章节明确写明 EEG 来自离线回放。

Kim 没有完整交代窗口精确起止点、重参考细节、所有训练超参数及 EEG 与仿真动作的对应规则。不能将猜测写成原文设置。原文描述也不能代替对下载文件的实际检查。

本项目当前 proposal 使用训练/验证/测试参与者划分，主比较有 3 名测试参与者；这不是完整的 12 折 LOSO 复现。本阶段默认落实项目 proposal，完整 LOSO 不作为必做项。

在 `reports/protocol_decisions.md` 中记录每项设置的来源：文献明确规定、数据文档/文件确认、官方模型接口要求或项目自行选择。所有影响结果的选择在正式训练前固定。

3. 检查参与者 ID、实际通道与通道类型、采样率、数值单位、事件代码、事件时间、已有滤波/重参考/切片状态、坏通道和缺失文件。
4. 明确机器人动作事件与 error/non-error 标签的映射。严禁默认某个数字事件码就是 error；必须给出文档或文件证据。
5. 确认切片窗口的事件原点与起止时间。若关键标签或事件定义无法可靠确定，停止依赖它的训练，提交明确的阻塞说明；可以继续无关的代码与模型接口工作。

## 4. 数据划分与防止泄漏

### 默认协议

- 按参与者划分，两个模型共享同一份划分文件；禁止将同一参与者的 trials 随机分散到训练/验证/测试中。
- 保留 3 名测试参与者。若审计确认 12 名均可用，默认 2 名验证、7 名训练。
- 尚未指定具体参与者 ID。实现者可以在数据审计后，使用排序后的可用 ID 和固定随机种子 42 生成一次划分；记录使用的随机数库、版本和最终 ID。不得根据模型表现重抽划分。
- 若有效参与者不足，先报告原因并记录替代协议，不能悄悄减少测试人数或复用测试参与者。
- 将具体 ID 写入 `configs/splits.json` 并保存校验值；正式训练前冻结。

### 使用规则

- 训练集：拟合网络及任何跨样本估计的预处理统计量，数据增强仅用于训练集。
- 验证集：早停、超参数选择、分类阈值及概率校准。可以共用验证集，但须记录选择过程；不要把验证指标作为无偏最终结果。
- 测试集：协议固定后的最终评估及反馈概率导出。不得用测试标签训练、校准、挑选 checkpoint 或决定预处理设置。
- 固定的单 trial 归一化若用于推理，可作用于测试 trial，但规则必须事先固定；禁止使用测试参与者的整体分布重新拟合归一化。
- 允许后续反馈模拟按测试 trial 的真实标签采样。这与用测试标签拟合 EEG 解码器不同，需要在报告中解释清楚。

## 5. 预处理与公平输入

- 保持相同有效 trial 集合、标签、通道选择原则及物理事件时间窗。
- Kim 的 256 Hz / 1–20 Hz / 2 秒描述作为参考，先核对数据已有处理，再确定可执行配置，避免重复或冲突的处理。
- CBraMod 的采样率、patch 长度、通道及幅值尺度按照选定官方 checkpoint 的输入规范核实。不要将 EEGNet 的输入张量原样硬塞给 CBraMod。
- 如两个模型需不同采样率或张量格式，只做必要适配，并明确记录。保持相同物理时间窗；改变带宽或归一化方案也要记录为比较因素。
- 保存完整处理配置：事件映射、窗口、滤波、重参考、重采样、通道顺序、单位转换、归一化及数据质量规则。
- 若某个模型因输入问题无法使用某些 trials，应先解决适配；必须排除时同步应用于主比较双方并报告，不得静默制造不同测试集合。
- 为 trial 建立稳定 ID，建议使用参与者、条件、源文件和源事件索引组合。两个模型都使用它，不能用 DataLoader 的临时行号。

建议保存 `trial_manifest`，至少包含 `subject_id`、`trial_id`、源文件、原始事件索引/时间、原始事件码、标签、split、保留状态与排除原因。

## 6. 两个解码器

### EEGNet

- 从头训练特征提取网络与二分类头。
- 参考 https://github.com/vlawhern/arl-eegmodels ，记录结构、超参数、实现来源和版本。
- 如采用 PyTorch 移植版，说明来源并核对关键层、输入布局及输出类别顺序，不能仅凭模型名称认为实现相同。

### CBraMod

- 代码：https://github.com/wjq-learning/CBraMod
- 权重：https://huggingface.co/weighting666/CBraMod
- 记录确切代码 commit、权重文件、revision 和 SHA-256。
- 加载预训练 backbone，接二分类头；默认执行全模型微调，以符合 proposal 的 fine-tune 方案。
- 若显存限制要求冻结部分层或只训练分类头，先尝试调整 batch size / 梯度累积；仍需改变训练方式时，显式记录为协议偏离，不把 linear probe 冒充全模型微调。

### 共同规则

- 标签统一为 `0 = non-error`、`1 = error`；对外输出永远是 `P(error)`。
- 允许采用不同学习率和模型所需输入适配；公平性不是所有超参数机械相同，而是相同数据划分、透明的验证选择规则和明确的搜索预算。
- 默认先用 decoder seed 42 各完成一个正式训练；这是最低交付要求，不声称已测量解码器训练种子的波动。额外 decoder seeds 应另列，不能与未来 RL seeds 混淆。
- 类别不平衡时，仅使用训练集信息选择加权损失或采样策略，记录其对概率校准的影响。
- 保存最佳验证 checkpoint，明确选择指标与早停规则；不能默认最后一轮就是最佳模型。

## 7. GPU 执行顺序

1. 记录硬件、GPU 显存、驱动、框架和依赖版本，建立独立环境。
2. 完成数据审计、固定划分和协议决策，再开始正式训练。
3. 用小批次验证两个模型的输入形状、单位、标签方向、loss 有限性与 checkpoint 加载；检查训练集小样本拟合能力。
4. 各跑短训练，记录稳定后的每 epoch 时间、峰值显存和样本吞吐，估算正式运行耗时。不把短测结果作为正式比较结果。
5. 使用配置文件完成 EEGNet 训练和 CBraMod 微调，保存日志与最佳 checkpoint；支持中断恢复。
6. 在验证集上完成校准，再执行最终测试评估与导出。
7. 固定网络和校准参数，以 eval 模式生成预测；导出时关闭 dropout，并禁止更新 BatchNorm 统计量。

不要由本文猜测 GPU 总小时数。把实际训练预算、epoch 上限、早停 patience、调参候选数写入配置，并报告实测耗时。无可用 GPU 时可完成数据和 EEGNet CPU 调试，但不能将未运行的 CBraMod 训练报告为完成。

## 8. 校准与评估

- 至少输出 AUROC、balanced accuracy、Brier score；同时报告正负样本数、混淆矩阵及分类阈值。
- balanced accuracy 默认使用 `P(error) >= 0.5`；若另用验证集选阈值，单独报告，并保存阈值。
- 输出 pooled 测试结果、逐测试参与者结果及参与者宏平均。说明样本数和平均方式；没有独立重复实验时，不伪造 seed 标准差或显著性结论。
- AUROC 遇到单类别子集时报告不可定义及原因，不能填 0 或静默丢弃。
- 概率校准默认可使用仅在验证集拟合的 temperature scaling，或事先记录的其他方案。保存校准参数；若不校准则明确使用 identity。
- 分别报告原始概率和校准后概率的 Brier score；不得因为某个方案在测试集表现好才决定采用它。
- 本阶段只判断解码性能，不提前声称某模型一定能提升后续 RL。

## 9. 交给 RL 的数据接口

输出长表 `artifacts/predictions/test_predictions.csv`，每行对应一个 trial 在一个模型/decoder seed 下的预测。最低字段：

```text
subject_id,trial_id,label,split,model,decoder_seed,p_error_raw,p_error,checkpoint_id,preprocessing_id,calibration_id
```

- `model` 使用 `eegnet` 或 `cbramod`；`split` 在此文件中应为 `test`。
- `p_error_raw` 为未经校准的错误概率；`p_error` 为最终反馈概率。使用 identity 校准时两列相同。
- 所有概率有限且位于 [0, 1]。标签和 subject ID 必须能连接回 trial manifest。
- 两个模型在同一 decoder seed 下覆盖相同测试 trial IDs，且对应标签完全一致。
- `checkpoint_id` 等标识通过 `artifacts/manifest.json` 解析到配置、文件路径、版本及校验值。
- 验证集预测若需保存，应另存文件，不混入 RL 测试反馈库。

RL 阶段之后才会按动作片段的模拟标签抽取 trial，然后读取该 trial 的概率。本阶段不要预先应用 `1-p`、`0.5-p` 或反馈权重；保留概率，使后续奖励设计可以独立调整。

## 11. Checkpoint 保留、Release 与远程交付（必做）

### 保存什么

每个正式 model / decoder seed / split run 使用独立 run ID，至少保留：

- `best.ckpt`：按预先固定的验证指标选择的最佳 checkpoint，用于最终预测。
- `last.ckpt`：最近完成的训练状态，用于中断恢复；不能只存最终分类头。
- 完整模型参数（backbone 与分类头）、optimizer、scheduler、AMP scaler（如使用）、epoch/global step、最佳指标、Python/NumPy/框架 CPU/GPU 随机数状态，以及 sampler/generator 状态（如使用）。不适用字段明确标记，不伪造完整恢复能力。
- 模型结构、训练配置、标签方向、数据划分与 trial manifest、预处理参数、归一化统计量、校准参数、依赖版本和源码 commit。
- 训练日志、最终 metrics 和逐 trial 概率表。保存所有正式 runs 的最佳与最新 checkpoint，不能只保留表现最好的模型。

在 epoch 边界保存可恢复状态，使用原子写入以防中断损坏。固定间隔另存周期 checkpoint；保存频率及保留数量在训练配置中明确。至少每个完整 epoch 更新 `last.ckpt`，验证指标改善时更新 `best.ckpt`。最终交付时保留所有仍保留的周期 checkpoint，不在上传核验前清理本地产物。

### 验证与交付

1. 在正式长训练前检查 GPU、仓库 push 权限和 Release 上传权限；权限缺失时明确报告，不能等临时机器销毁才发现产物无法导出。
2. 在长训练过程中定期备份最近 checkpoint 到可持久保存的位置；最终位置仍为项目 GitHub Release。
3. 上传后从 Release 下载到新的本地目录，核对文件大小与 SHA-256，不能仅以命令退出码判断成功。
4. 用下载的 `best.ckpt` 重跑一个固定样本集推理，在声明容差内复现概率；用下载的 `last.ckpt` 进行一次独立的短恢复检查，保护原 checkpoint，确认训练状态可加载和继续。
5. 将 Release URL、tag、源码 SHA、附件清单、大小、校验值、下载/解包/推理/恢复命令写入并提交 `reports/artifact_index.md`。Release 对应训练源码 SHA；索引文档可以作为之后的单独提交，不移动原 tag。
6. 最终回复同时给出仓库链接、代码 commit、Release 链接及所有未完成项。未成功上传 checkpoints 或下载校验失败时，必须标为交付未完成，并保留本地文件。
