## 3. Recording properties (from the files)

- Sampling rate: 256 Hz in every file (EEGLAB `srate`; setname ' resampled'). The documentation states recording at 1000 Hz and downsampling to 256 Hz, consistent with the files.
- Channels: 30 per file = 27 scalp EEG + EOG1, EOG2, EOG3. TP9/TP10 (the documented reference electrodes) are absent, and CP1/CP2 are present although the documentation's electrode list omits them. MNE reports all 30 as type `eeg`; EOG channels are identified by name.
- Reference: documented as the average of TP9 and TP10 (linked mastoids) for EEG and EOG. The EEGLAB `ref` field says 'common', which is EEGLAB's default label and does not contradict the documentation. The absence of TP9/TP10 is consistent with the mastoid reference having been applied before release.
- Units: microvolts (MNE reads EEGLAB data as uV). Raw channels carry large DC offsets (median |x| of hundreds to >10,000 uV) and drift, i.e. no high-pass filter was applied before release. Continuous data, single segment (`trials` = 1); no prior epoching.
- Bad channels: none are marked in the files. No channel was removed for quality reasons by us; no amplitude-based trial rejection is applied (see Section 6 for the amplitude distribution).

## 4. Events and label mapping

Documented markers (PDF p. 3): S1/S2/S3 stimulus left/up/right; R1/R2/R3 response key; S4 feedback no error; S5 feedback human error; S6 feedback machine error; FB1/FB2/FB3 feedback left/up/right; S7 colour-frame feedback; S8 robot head moving back; S9 end of trial.

Evidence from the files (all 12 robot files, 500 trials each = 10 blocks x 50, as documented):

1. Each file holds 500 stimulus, 500 response, 500 FB, 500 outcome (S4+S5+S6), 500 S7, 500 S8 and 500 S9 markers (plus one 'empty' boundary event), and every parsed trial has all four of stimulus/response/FB/outcome (0 trials excluded as incomplete).
2. **FB always equals the response key** (all 6,000 trials). FB therefore records the commanded feedback direction; a machine error is not visible in the direction markers.
3. **S5 (human error) <=> response != stimulus** in all 178 S5 trials; all S4 and S6 trials have response == stimulus. 0 trials violate these rules (`outcome_consistent_with_directions`).
4. **S6 rate matches the documented pErr design.** Overall S6/(S4+S6) = 2055/5822 = 0.353, the mean of the documented pErr1 = 20% and pErr2 = 50%. The 120 per-block rates are bimodal (60 blocks < 0.35, median 0.20; 60 blocks >= 0.35, median 0.50), as expected for pseudo-randomised 20%/50% blocks.

**Label mapping used (frozen):** `S4 -> 0 (non-error)`, `S6 -> 1 (error)`. S5 (human error) trials are excluded: the robot correctly executed a wrong key press, so the observed robot action was not a robot error, and the response error confounds the potential. S6 is confirmed as the robot (machine) error by the documentation and by the block-rate evidence above; it cannot be cross-checked against direction markers (item 2).

## 5. Event origin and epoch window

| interval (256 Hz samples) | min | max | per-file medians | median ms |
|---|---|---|---|---|
| resp_to_fb_samples_right | 9 | 35 | 13 to 19 | 51-74 |
| resp_to_outcome_samples | 33 | 83 | 34 to 35 | 133-137 |
| fb_to_outcome_samples | -2 | 73 | 15 to 18.5 | 59-72 |
| fb_to_s7_samples | 54 | 126 | 71 to 74 | 277-289 |
| fb_to_next_stimulus_samples | 431 | 63660 | 624 to 649 | 2438-2535 |
| resp_to_fb_samples_up | 9 | 35 | 21 to 33 | 82-129 |
| resp_to_fb_samples_left | 9 | 36 | 14 to 18 | 55-70 |

- The documentation's timeline: (c) key press = start of robot head movement, (d) end of head movement 130 ms later, (e) colour frame 200 ms after (d). The outcome markers S4/S5/S6 occur at a constant response + 34-35 samples (133-137 ms) = (d); S7 follows FB by ~280 ms = (e).
- FB follows the key press by a direction-dependent lag in the robot files (median 13-19 samples for left/right, 21-33 for up), unlike a fixed software delay; it is the marker the documentation names 'Feedback <direction>'.
- **Chosen origin: the FB marker** (documented feedback-direction event, the earliest marker attached to the robot's feedback). Kim's papers state only '2-second windows aligned to the feedback onset'. The alternative origins (key press R, 47-130 ms earlier; outcome marker, up to ~70 ms later) differ by < 140 ms; this residual ambiguity is recorded as a limitation.
- **Window: [0.0, 2.0) s after FB** = 512 samples at 256 Hz. No baseline correction (the 1 Hz high-pass removes offsets).
- The next trial's stimulus follows FB by 1.68 s at minimum (per-file medians 2.44-2.54 s), so in a minority of trials the 2 s window includes the next stimulus onset and the robot's return movement (S8, ~0.6 s). Both events occur independently of the label (pseudo-random design).
